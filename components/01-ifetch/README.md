# 01-ifetch — 프로그램 RAM 과 명령 페치

## 목적

`pc` 가 가리키는 32비트 명령을 프로그램 RAM 에서 읽어 디코더에 넘긴다. 하버드 구조라
데이터 RAM(07-lsu)과 분리돼 있고, `fence.i` 는 nop 다.

## 핀

| 이름 | 폭 | 방향 | 설명 |
|---|---|---|---|
| `pc` | 64 | 입력 | 00-pc |
| `instr` | 32 | 출력 | 현재 명령 워드 (02-decoder 로) |

## 내부 설계

```
prog_ram: 프로그램 RAM (게임이 어셈블한 프로그램을 여기에 올린다), 종류는 지연 없는 것(B2), endianness 설정 확인(B7)
load:     Load port(32) — address = pc (바이트 주소), enable = On
instr   = load.out
```

게임 RAM 이 바이트 단위 주소(B4)가 아니라 워드 단위면 `pc >> 2` 를 주소로 준다.
로드 포트에 1틱 지연(B2)이 있으면 2상 클록으로 바꾸고, 페치 틱에 읽은 값을
`Register(32)` 에 잡아 실행 틱에 쓴다.

## 게임에서 만들기

1. RAM 부품(빠른 RAM)을 놓는다. 이 엔진에는 별도 Program 부품이 없고(실행 파일 부품 id 에 com_program 없음) RAM 이 프로그램 메모리다. 부품의 "프로그램 편집" 아이콘으로 IDE 를 열면 `spec.isa` 탭과 `.asm` 탭이 있다.
2. `Load port` 를 붙이고 폭 32, 주소 입력에 `pc`, enable 에 `On`.
3. 출력에 `instr` 라벨.
4. 파운드리 부품으로 만들 필요는 없다. 상위 보드에 직접 둔다(프로그램 RAM 은 레벨/아키텍처 고정 부품일 가능성이 큼).

## 검증

`tests/encode_check.asm` 을 올리고 `pc = 0` 에서 `instr = 0x00500093`, `pc = 4` 에서 `0xFFF00113` 인지 본다.
뒤집혀 보이면 B7(엔디언 이중 적용)이다.

## 상태

설계 문서만 있음. 바이트 주소(B4)와 폭별 로드 포트는 게임 캠페인 문구로 예상됨(검증표 0절).
