# 하드웨어 모듈

모듈 하나가 파운드리 커스텀 부품 하나이자 허브 업로드 단위입니다. 폴더마다 `README.md` 에
목적, 핀, 내부 설계, 게임에서 만드는 순서, 검증 방법을 적고, 회로가 완성되면 같은 폴더에
캡처(`*.png`)와 허브 링크·게임 내 부품 이름을 기록합니다.

| 폴더 | 모듈 | 단계 | 상태 |
|---|---|---|---|
| `00-pc` | PC 레지스터와 다음 PC 선택 | 2 | 설계 문서 |
| `01-ifetch` | 프로그램 RAM 과 32비트 명령 페치 | 2 | 설계 문서 |
| `02-decoder` | 명령 필드 분리, opcode 판별, 제어 신호 | 2 | 설계 문서 |
| `03-imm-gen` | 즉시값 생성기 (I/S/B/U/J) | 2 | 설계 문서 |
| `04-regfile` | 정수 레지스터 파일 x0~x31 | 2 | 설계 문서 |
| `05-alu` | 64비트 ALU (W형 포함) | 2, 5 | 설계 문서 |
| `06-branch` | 분기 비교기와 점프 대상 계산 | 3 | 설계 문서 |

| `10-amo` | A 확장 (lr/sc/amo) | 8 | 설계 문서 |

## 공통 규약

- 폭: 데이터 경로 64비트, 주소 64비트(실제 RAM 은 훨씬 작음), 명령 32비트.
- 신호 이름은 소문자 + 밑줄. 1비트 제어 신호는 `is_*`, `*_en`, `*_sel`.
- 부품 이름은 게임 표기(`Add`, `Mux`, `Splitter` 등)로 적고, 폭 설정값을 괄호에 쓴다: `Add(64)`.
- 각 모듈은 파운드리에 `RV64G/<모듈 이름>` 으로 저장한다. 캠페인용 `Overture/*`, `Hint */*` 폴더는 건드리지 않는다.
- 게임 GUI 로 만든 회로는 여기 저장소에 바이너리(`circuit.data`)로 넣지 않는다. 허브에 올리고 링크와 캡처만 남긴다. (바이너리 형식이 문서화되지 않았고 엔진 버전에 묶여 있어서.)
